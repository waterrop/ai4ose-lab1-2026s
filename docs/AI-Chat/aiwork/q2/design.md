# 面向AI时代的Rust+RISC-V64操作系统课程实验设计方案

## 整体设计理念
本方案以“模块化、可组合、AI赋能、个性化扩展”为核心，采用Rust语言与RISC-V64架构，打破传统OS实验“大黑盒”的痛点。通过构建“微实验（Micro-Labs）”到“组合实验（Macro-Labs）”的进阶路径，结合AI调试助手，帮助学生从零构建一个现代操作系统，形成完整的OS知识图谱。

## 一、 实验整体架构设计（模块化与可组合）

实验分为“独立小实验（基础模块）”与“组合型实验（综合系统）”两个层级。每个小实验拥有独立的Git仓库或Cargo Workspace，保证代码精简，聚焦单一知识点。

### 1. 独立小实验（Micro-Labs）
- **Lab 1: 裸机启动与输出 (Boot & UART)**
  - **核心概念**：物理内存布局、RISC-V特权级（M态到S态的切换）、SBI调用。
  - **Rust特性**：`#[no_std]`环境配置、内联汇编、全局可变状态的安全封装。
- **Lab 2: 中断与异常处理 (Trap & Interrupt)**
  - **核心概念**：CSR寄存器（`stvec`, `sepc`, `sstatus`）、上下文保存与恢复。
  - **Rust特性**：裸指针操作、生命周期与硬件生命周期的映射。
- **Lab 3: 物理内存与页表管理 (Memory Management)**
  - **核心概念**：Sv39多级页表机制、缺页异常（Page Fault）、物理页帧分配器。
  - **Rust特性**：所有权语义在物理页帧管理中的应用（Drop Trait自动回收内存）。
- **Lab 4: 进程与线程抽象 (Process & Thread)**
  - **核心概念**：进程控制块（TCB）、内核栈与用户栈、上下文切换（Context Switch）。
  - **Rust特性**：`Arc<Mutex<T>>`在并发状态下的安全共享。
- **Lab 5: 基础调度算法 (Scheduling)**
  - **核心概念**：协作式与抢占式调度、时间片轮转（RR）、时钟中断。
- **Lab 6: 极简文件系统 (Simple FS)**
  - **核心概念**：块设备接口、索引节点（Inode）、目录与文件抽象。

### 2. 组合型实验（Macro-Labs）
学生在完成小实验后，通过引入包管理（Cargo Dependency）将小模块组合成完整的OS：
- **组合实验 A：多任务协作内核 (Lab1 + Lab2 + Lab4 + Lab5)**
  - **目标**：实现支持多道程序并发运行的批处理系统。
- **组合实验 B：支持虚拟内存的时分复用系统 (组合 A + Lab3)**
  - **目标**：实现各进程地址空间隔离，彻底解决内存冲突，理解虚拟内存的保护机制。
- **组合实验 C：功能完备的通用OS (组合 B + Lab6)**
  - **目标**：实现支持标准输入输出、文件读写、进程间通信的综合型操作系统。

## 二、 实验指导手册设计（启发式知识图谱）

传统的“Step-by-Step”手册容易让学生沦为“代码搬运工”。本手册采用“引导式、启发式”框架：

### 手册核心框架（以 Lab 3: 内存管理为例）
1. **本章知识定位（Knowledge Graph）**
   - **前置依赖**：Lab 2 的异常处理（用于捕获缺页异常）。
   - **当前定位**：为 Lab 4 的进程隔离提供基础设施。
   - **后续延伸**：为写时复制（COW）、mmap映射提供底层支持。
2. **核心概念与重难点剖析**
   - **理论概念**：为什么需要Sv39？虚拟地址到物理地址的转换过程图解。
   - **易错点提示**：页表项（PTE）标志位设置错误导致Load/Store Page Fault；TLB未刷新导致的幽灵Bug。
3. **Rust与RISC-V架构的交汇**
   - **安全机制**：展示如何利用Rust的类型系统（Type State Pattern）来区分“物理地址”、“虚拟地址”和“页表项”，在编译期消灭地址混用错误。
4. **探究与思考问题（Heuristic Questions）**
   - “如果两个进程共享同一个只读物理页，在Rust代码中应该如何安全地表达？”

## 三、 AI辅助工具与调试增强设计

为解决OS实验“一跑就崩、一崩就懵”的痛点，引入深度定制的调试生态：

### 1. 轻量AI调试助手：`riscv-os-debug-ai`
- **运行机制**：作为VS Code插件或命令行工具，拦截`cargo run`和QEMU的输出。
- **核心功能**：
  - **崩溃日志解析**：自动捕获QEMU的`Store/Load Page Fault`或`Illegal Instruction`。
  - **智能归因分析**：将RISC-V的`scause`、`sepc`与Rust源码映射。例如，AI分析出：“寄存器`scause`显示Load Page Fault，虚拟地址为0x0，定位到`mm/page_table.rs:45`。这是因为在页表遍历时遇到未初始化的空指针，建议检查页帧分配器是否正确清零。”
  - **OS概念解答**：学生可直接提问“为什么在内核态还会触发Instruction Page Fault？”，AI结合当前Lab的上下文给出针对性解释。

### 2. 调试增强：自定义强大的 `panic_handler`
- **实现原理**：重写Rust的`#[panic_handler]`。
- **输出增强内容**：
  - **寄存器快照**：Panic瞬间的通用寄存器（a0-a7, sp, ra等）及特权寄存器（sstatus, sepc, stval）状态。
  - **调用栈回溯（Backtrace）**：利用栈帧指针（`fp`）向上遍历，打印内核函数的调用链条。
  - **错误类型推断**：对异常地址进行区间判断（如：落入内核栈保护页提示“Kernel Stack Overflow”；落入零地址提示“Null Pointer Dereference”）。

## 四、 个性化扩展与核心目标实现

本方案拒绝“一刀切”，提供不同梯度的个性化挑战路线，培养创新能力：

### 1. 基础要求（巩固概念）
完成所有核心小实验与组合实验，能够成功运行多进程并支持基本的文件读写。建立“理论-代码-架构”的闭环认知。

### 2. 个性化扩展方向（自选其一进行深度探索）
- **性能优化方向**：将默认的FIFO页替换算法修改为Clock算法或LRU算法；将简单的进程调度器替换为完全公平调度器（CFS）或多级反馈队列（MLFQ）。
- **功能增强方向**：实现`fork`的写时复制（Copy-on-Write）机制；增加简单的管道（Pipe）机制支持进程间通信。
- **安全加固方向**：利用Rust特性，设计更加安全的系统调用接口层，防范用户态恶意传入非法指针。

### 3. 能力评估与反馈
通过`riscv-os-debug-ai`记录学生的报错频率、常犯错误类型，为教师提供学情分析面板，帮助教师精准干预，实现真正的因材施教。

> **结语**：这套实验方案通过“Rust+RISC-V”的现代化技术栈保证了代码的先进性，通过“模块组合”降低了认知负荷，通过“AI调试助手”扫清了实操障碍，最终引导学生在底层系统中自由穿梭，培养出真正的系统级架构思维与解决复杂问题的能力。
